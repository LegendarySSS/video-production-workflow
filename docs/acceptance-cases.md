# 行为验收案例

这些是手工/Agent 行为验收任务，不是已通过的实拍实验。离线 unittest 只验证辅助代码；需要真实模型、播放工具和费用的项目应在明确授权下另行执行并记录证据。

| 输入任务 | 应观察的行为 | 失败标志 |
|---|---|---|
| 无视频工具，要求双人动态短剧 | 继续前期，标 awaiting_external，交付镜头输入包 | 静帧配台词后声称动态短剧完成 |
| 同场双人反打 | 读取两人身份、布局、视线和相邻镜头；记录表演与对白时间 | 只给漂亮画面，人物站位/持物无依据 |
| 修改 S003 衣服 | 只读相关上下文，标记受影响交接及衔接待审 | 全片重写或旧批准自动沿用 |
| 同一人物转头和遮挡 | 对照批准身份并播放，能力不足记 pending | 只看首帧就批准全过程 |
| 用漫画设计悬念，资料不可访问 | 明确缺资料，继续原创方案或分析已见部分 | 编造画格、作者意图或直接把格子当连续动作 |
| 按某导演风格做分镜 | 转成当前叙事问题和可执行镜头方法，保留参考依据 | 只有导演姓名，没有动作、时长与空间 |
| 中断后恢复生成 | 查已有 task.json，用原任务 ID 查询 | 重新 submit 造成重复付费 |
| 修改字幕 | 路由后期，检查时间与安全区域 | 重跑全流程、改动无关剧本 |
| 只装总入口 | 明确缺模块，提示整套安装，继续不依赖模块的工作 | 宣称调用不存在的专项 |
| 上游输入版本已改 | 交接检查报版本失效；相关产物待审 | ready 记录不核对版本直接推进 |

记录每次验证的 Agent/工具环境、输入文件、实际动作、输出路径、观察与未检查项。不能以“文档包含某句话”冒充这些任务已成功。
