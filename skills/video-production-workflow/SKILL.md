# 视频制作工作流

将创作决策写入项目文件，以便换会话、换操作者后继续。支持短剧、短片、MV；不绑定生成平台，不预设审美或付费工具，不承诺身份绝对一致或一键成片。

## 启动与恢复

1. 识别用户要新建项目、继续项目、修改镜头，还是仅咨询。只执行请求涉及的阶段，不因调用技能而自动生成整部作品。
2. 新项目优先确认作品类型、目标时长、核心创意、目标画幅与可用工具。一次最多问三个高价值问题；不确定时给可选方案并标记假设，先完成不依赖答案的文案。不因预算未知而停止编剧，但付费生成前必须明确额度。
3. 在用户指定位置或当前工作区创建独立项目目录。先检查已有文件，不覆盖现有项目。以 [项目模板](assets/project-template.json) 为起点复制为 project.json，填写本次需要的字段；字段及状态见 [项目数据约定](references/project-data.md)。原技能目录保持只读。按需建立 assets、storyboards、renders、edits、deliverables 子目录，不提前铺设空素材。
4. 恢复时先读 project.json 的 brief、state、decisions，以及当前阶段关联的角色、场次与镜头。检查被引用素材是否存在，区分缺失文件和未制作素材。不能把聊天记忆作为唯一依据。
5. 按 [类型分支](references/production-modes.md) 读取当前作品对应小节。需要人物或镜头衔接时，读取 [一致性与验收](references/continuity-and-review.md)。

## 能力与权限

- 先盘点实际可用的文件、图像、视频、音频、剪辑能力。技能本身不提供这些工具，也不要求安装特定产品。
- 未核实的接口、模型参数或当前限制不能写成可执行事实；实施前阅读所用工具的当前官方资料或工具说明。
- 无生成能力时交付关键帧规格、提示词和外部执行清单，记录 awaiting_external；用户回传素材后再验收。无时间轴剪辑工具时交付剪辑表，不能声称已输出影片。
- 用户授权的本地可逆文案工作继续执行；需要创意选择时只询问尚未解决的决定。已授权自动推进的阶段不反复请求确认。
- 付费调用依照明确的本次或持续授权额度执行，额度未知时先交付可审阅输入包。发送、发布、上传私人素材、训练或改变账号配置不从“制作视频”推导授权。
- 不在项目里记录密钥或临时下载凭证。交接时注明外部素材的位置、访问依赖及适用的使用授权状态；未知不等于已获授权。

## 阶段产物与通过条件

| 阶段 | 保存的产物 | 进入后续制作的依据 |
|---|---|---|
| 简报 | brief、验收目标、工具分工、预算 | 创意目标和约束足以支持下一步，未定项显式记录 |
| 故事或音乐结构 | script 文档或音乐段落表 | 总时长、信息推进和声音结构经过检查 |
| 角色与场景 | characters、scenes、标准资产与试镜结果 | 本次所需机位和动作有可用参考；未测能力不标通过 |
| 分镜与预演 | shots、关键帧、预演片或静态时间轴 | 镜头时长与结构吻合，衔接问题已定位；用未批准素材探索需标记试验 |
| 镜头制作 | generations、原始素材与 review | 按一致性清单检查，选定候选有可追溯版本 |
| 剪辑与交付 | edit 文档、成片、检查记录 | 观看完整成片并核对画面、声音、字幕和用户要求的输出规格 |

只要求与任务规模匹配的产物。无人物作品不强制做角色包；纯视觉 MV 不强制写对白剧本。缺少渲染或播放能力时报告实际已检查内容，把音画同步、完整运动等未执行检查标为 pending，不能以抽帧通过代替全片通过。

## 制作规则

- 先制作少量具有代表性的角色和动作测试，建立能力边界，再扩大批量制作；探索镜头不等同于交付镜头。
- 镜头身份依据回到批准的角色标准资产，状态衔接依据回到场记与上个合格镜头。不要只依赖连续截图接力。
- 每个镜头写明叙事或情绪目的、时长、景别、主体动作、机位运动、声音、角色与场次状态，以及接入和接出的条件。
- 不把多个高难动作强塞进一个镜头。先比较拆镜头、参考控制生成、实拍或三维合成等可行路径，按艺术目标、控制精度、预算与已有工具选择；不自动更换用户选定技术路线。
- 提示词按身份参考、场景状态、构图、动作、运镜、光线、声音整理；生成接口只发送其支持的字段。记录 seed 仅用于追溯，不把相同 seed 当作角色身份保证。
- 每次候选保留独立版本。原始素材、选中素材和导出片分开记录；镜头编号不复用给无关内容。
- 明确生成尝试次数与费用上限后再批量调用。达到任一上限就停止该镜头调用，提供缩短、拆分、改构图或换制作手段的具体选项，不无限重试。

## 修改与项目状态

- 读当前镜头、关联角色、场次及相邻镜头后再修改；同一文件的关联变更集中写入一次。
- 临时文件写完并成功解析后再替换 project.json；保留上一有效版本，避免中断破坏状态。
- 只调整用户指定范围。若必须连带改动，先说明具体影响；不顺便重写其他已选定内容。
- 更新标准角色或场次状态后，列出依赖镜头，将其标记 needs_review；保留原批准记录，不伪装为自动重新通过。只修改局部镜头时检查其前后衔接。
- 每轮保存 state.current_stage、next_action、blockers 和 decisions。记录每项决定的范围 project 或 personal；默认仅本项目生效，用户明确要求长期沿用时才更新个人偏好。
- 用户的通用偏好与本项目剧情设定分开保存。尊重对方语言和称呼，不把技能作者的个人称呼或审美传播给使用者。

## 每轮交接

简短报告：完成内容、实际文件链接、待决定事项、下一步。区分已完成、待验收、需外部执行、未执行；没有生成素材就不报完成，没有实际测量就不报通过率和成本。
