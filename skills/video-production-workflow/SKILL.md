# 视频制作总工作流

用户只需描述创作目标；由本入口选择当前阶段，不要求用户理解模块名称。专项技能是同一 Agent 按需读取的工作说明，不代表自动启动多个 Agent，也不提供后台调度服务。

## 启动与恢复

1. 识别新建、继续、局部修改或咨询，只执行授权范围。新项目确认类型、时长、创意、画幅与可用工具，一次最多问三个关键问题；先推进不依赖答案的前期文案。
2. 在独立项目目录使用 [项目模板](assets/project-template.json)，技能目录只读。已有项目先读取 brief、state 和与当前任务有关的决定，不能覆盖文件或依赖聊天记忆。字段见 [项目数据](references/project-data.md)。
3. 按下表只读取当前专项 SKILL.md 和它要求的参考；不要一次加载所有技能。相对路径基于本文件所在目录；若安装器位置不同，按技能名称定位真实目录，不能猜路径。缺模块时报告安装不完整，并继续不依赖它的工作，不能声称已执行缺失模块。
4. 执行前读 [阶段交接约定](references/workflow-contracts.md) 对应阶段。可用 scripts/workflow.py 离线提取镜头上下文、检查交接结构；工具不会验证艺术质量、批准作品、修改项目或执行付费调用。

## 路由

| 阶段 | 专项技能 | 加载条件 |
|---|---|---|
| brief | 本入口 | 简报、交付约定、工具盘点 |
| story | [video-story](../video-story/SKILL.md) | 剧本、节奏或音乐段落 |
| design | [video-design](../video-design/SKILL.md) | 角色身份、视觉与场景状态 |
| storyboard | [video-storyboard](../video-storyboard/SKILL.md) | 分镜、表演调度、参考分析 |
| production | [video-shot-production](../video-shot-production/SKILL.md) | 动态试镜、镜头执行与候选 |
| post | [video-post](../video-post/SKILL.md) | 剪辑、声音、字幕与交付验收 |

阶段可以按任务跳过不适用部分，但要写明理由。纯视觉 MV 不强制人物和对白；仅修改字幕不重走剧本。专项完成后回到总入口更新项目状态。

## 不可丢失的制作约束

- 短剧默认 dynamic_video。静态分镜、配音预演与动态漫画需明确标注，不能自动替代动态短剧。短剧制作读取 [动态要求](references/dynamic-drama.md)。
- 批量制作前，先制作并播放验收一个覆盖本片动作及必要对白的动态试镜；前期咨询不要求付费试镜。图片推拉、字幕运动和 MP4 扩展名不能证明完成表演。
- 盘点实际文件、图像、视频、音频、剪辑和播放能力；缺动态来源保存 awaiting_external 并交付输入包，缺剪辑能力交付剪辑表。未执行检查标 pending。
- 付费生成需要本次或持续的明确次数与额度授权。已有授权不重复询问；授权不明时继续文案，先提供请求预览。API 开关不是金额封顶，不自动换供应商或无限重试。
- 参考人物身份回到批准标准资产，场景衔接回到场记与上个合格镜头；相同 seed 与角色编号不保证身份一致。
- 凭证只留本机，不发聊天、不入项目或版本库；API 任务记录可能含私密提示词及签名 URL，不公开分享。私人素材上传、发布与训练需要对应授权。
- 尊重使用者的语言与审美，不传播作者私人称呼。个人偏好与项目决定分开保存。

## 上下文、返工与交接

按 [阶段交接约定](references/workflow-contracts.md) 保存输入版本、输出位置、检查证据与未解决项。只有相关记录和素材进入当前工作上下文，不用所有历史候选填满上下文。

更新上游版本时，沿 handoffs.input_versions 追踪依赖，标记相关交接、镜头和交付物 needs_review，保留原记录；不全量重做，不把旧批准当新版本通过。仅改一个镜头仍检查其相邻镜头和所涉场记。

project.json 集中写入：重读最新版本，写临时文件、解析、保留上版，再替换；冲突时保留双方变更。每轮更新 current_stage、next_action、blockers、decisions 与交接记录。

简短报告实际完成内容、文件链接、未检查项和下一步。没有生成不报完成，没有测量不报成本或通过率。整套需同级安装本表六个技能；能力边界按当前实际工具记录，不向用户承诺一键成片。
